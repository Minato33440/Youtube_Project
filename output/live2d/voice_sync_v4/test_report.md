## 個別ルール

| 動き | 今回のルール |
| --- | --- |
| 口 | ParamMouthOpenY / ParamMouthFormをv3から全478フレームそのままコピー |
| まばたき | 文・句の区切り付近に4回。開始は約1.13 / 4.07 / 9.77 / 12.30秒。最小間隔2.2秒。左右同時に閉じ、速めに閉鎖→短く保持→ゆっくり開く |
| 呼吸 | 4秒周期の弱い基線。0.30秒以上の休止5か所で0.12だけ深める。加算部分は少なくとも1.4秒かけて滑らかに増減する |
| 首 | 原稿の「財源」「経済成長」「国債への不安」「暮らしを支える政策」に小さな傾きを配置。各動作の全幅0.68秒、中心は1.86 / 6.18 / 9.12 / 11.36秒 |
| 重なり | まばたき開始、呼吸の山、首の強調の山を全て同時には置かない。首は区切りのまばたきから離した語句中心 |
| 始終端 | 目は開き、首は中立。呼吸は冒頭0.5秒で入り、終端0.6秒で0へ戻す |

まばたきの8サンプルは `[1, .45, 0, 0, .25, .60, .84, 1]`。7区間で約0.233秒、完全閉鎖は2サンプル。閾値で全休止に挿入せず、今回は意味上の区切りから手動選定した。

呼吸の実値は0〜0.599957。既存リグが全体を100〜100.6%で微小伸縮する方式のため、今回の最大伸縮は概算約0.36%。胸・肩を独立して動かす変形ではない。首はParamAngleZ=-4.184083〜+3.785599で、現在のリグ対応では実角度はおよそ±0.8度以内。上下のうなずきではなく小さい左右の傾き。

休止は既存Julius音素整列から取得した。強調位置と左右の向き、まばたきの選択は編集上の演技設計であり、生理的な呼吸・まばたきを音声から測定したものではない。`events.json` に原稿・音素/モーラの照合窓と手動演出時刻を記録している。

## 検証結果

- 5本のMP4: 1280×720、30fps、478フレーム、15.933333秒。全体デコード成功。音声・映像開始時刻一致。
- 元動画からのPCMは同一。MP4音声のゼロオフセット相関は0.999983〜0.999986。
- v3の口2列と時刻列は文字列表現まで全フレーム一致。motion3の6曲線はCSVと値・時刻が一致。
- 各段階478枚を検査。まばたき単独では眼の範囲以外の画素変化なし。
- 連動版の開始・最終フレームはv3と画素単位で一致。
- 全フレームの不透明な内側領域に新しい透明画素を検出しなかった。これは輪郭から10px程度内側に絞った穴検出で、全形状の安全性を保証するものではない。
- 実行用モデルで目開閉1/.75/.5/.25/0、呼吸1＋首-30/-6/0/+6/+30を組み合わせた10姿勢を描画して目視した。使用範囲より大きい首傾斜も確認し、襟元に目立つ穴を認めなかった。
- まばたき8フレーム、強調・呼吸・終端を含む12枚、完成MP4の配置画像を目視した。`rig_calibration.png`、`blink_review.png`、`performance_review.png`、`composite_review.png` を保持。
- `model/Risa_performance.model3.json` のPerformanceグループをSDKに読み込み、motion3を実際に478ステップ再生した。6パラメーターのCSVに対する最大絶対差は0.001256以下（検査許容0.002）。直接CSVを設定して作ったMP4とは別に、モーション再生経路も確認済み。

機械検査: `verify_outputs.py` → `verification.json`。SDK再生検査: `verify_sdk_motion.py` → `sdk_motion_verification.json`。

v4の音声付き通し試聴による自然さの最終判定は未実施。既存の閉じ目は縦圧縮による直線的な表現で、閉じまぶたの曲線・まつ毛の厚みを作り込む余地がある。呼吸も上記の微小伸縮方式。今回の確認は、この簡易リグでの控えめな連動の実装・技術検査である。

## 再利用と再生成

入力設定は `performance_profile.json`。今の音声に対するまばたき・強調時刻も含むため、別音声では原稿と整列結果に合わせて置き換える。汎用的な閾値・周期と、音声ごとの時刻を区別する。別モデルでは標準パラメーターID、値の範囲、各値に対応する変形を確認・調整する。

リポジトリルートで、`output/live2d/runtime_venv/Scripts/python.exe` に各スクリプトを渡す。

1. `output/live2d/voice_sync_v4/build_coordination_curve.py` — 設定からカーブとmotion3を作る。
2. `output/live2d/voice_sync_v4/render_model.py --stage blink` — まばたき段階。
3. 同スクリプト `--stage breath` — 呼吸追加段階。
4. 同スクリプト `--stage all` — 全連動段階。
5. `output/live2d/voice_sync_v4/compose_video.py` — 音声付き5本を合成。
6. `output/live2d/voice_sync_v4/verify_outputs.py` と `verify_sdk_motion.py` — 検査。

モデル単体の姿勢確認は `render_model.py --calibrate`。実行用モデルはSDK 5.0形式、描画環境は既存のlive2d-py 0.7.0.4 / Cubism Core 5.1を使用。

SDKではPerformanceグループの0番を開始し、自動まばたき・自動呼吸を無効にして重複を避ける。音声の開始時刻をモーション0秒に揃える。モデル設定のSound参照だけで全ての外部アプリが自動で音声再生することを保証しない。フェードはモーション側で処理しているため登録上のFadeInTime/FadeOutTimeは0。別のidleやトラッキングと混ぜる際は同じパラメーターへの上書きと接続を確認する。

登録形式は[Live2D公式model3サンプル](https://github.com/Live2D/CubismWebSamples/blob/develop/Samples/Resources/Hiyori/Hiyori.model3.json)と[モーション設定の公式説明](https://docs.live2d.com/cubism-editor-manual/motion-setting/)を参照。今回のSDKでは一行JSONのmotion3がパースエラーとなり、インデントと末尾改行を付けた出力で読込・再生できた。原因の詳細は未確定だが、再生成コードも成功した書式に揃えている。
