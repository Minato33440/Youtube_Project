## 初回ルールと例外

実音声をFFmpegのsilencedetect（-40dB、0.15秒以上）で確認し、既存の強制音素整列の休止記号と突き合わせる。候補は0.24秒以上、整列との照合余裕は前後0.25秒。整列だけでは文末休止が短く記録されるケースがあるため、実音声の休止長を優先した。

吸気は音声休止の開始から最低30ms後、終了の最低35ms前までに収め、30fpsのフレーム境界へ内側に丸める。通常は約0.33〜0.37秒で吸い、短い文末休止では約0.17〜0.20秒の浅い補充にする。短い吸気の増加量は0.12以内。呼気は次の吸気までゆっくり減少する。両端の速度が0になる三次の補間曲線でつなぎ、急な形状切替を避ける。

| 吸気開始〜終了（秒） | 長さ（秒） | 呼吸パラメータ増加 |
| --- | --- | --- |
| 1.000〜1.333 | 0.333 | 0.111 |
| 2.600〜2.800 | 0.200 | 0.120 |
| 3.967〜4.333 | 0.367 | 0.141 |
| 5.400〜5.767 | 0.367 | 0.170 |
| 8.333〜8.500 | 0.167 | 0.120 |
| 9.700〜10.033 | 0.333 | 0.278 |
| 12.133〜12.500 | 0.367 | 0.205 |
| 13.867〜14.067 | 0.200 | 0.120 |

- 冒頭は発語まで約0.083秒しかない。無理に急吸気を入れず、約0.512の吸った姿勢から開始する。
- 7.31〜7.61秒の低音量区間は音素整列に休止の裏付けがなく、無声化の可能性を排除できないため吸気を入れない。
- 12.66〜12.82秒の短い区間では吸い直さない。
- 終端は次の発語がないため吸気を追加せず、約0.336で落ち着かせる。ゼロへの強制フェードを解除した。別の待機動画へつなぐ場合はこの終端値から接続を調整する。
- 長い無言区間の待機呼吸は、この16秒に対象がないため未実装・未検証。

今回の範囲は0.2755〜0.569833。上限はv8音声付きサンプルの最大0.593756以下とし、v8の変形自体は変えていない。提案時の0.25〜0.5秒は固定条件ではなく調整の出発点であり、短い休止では上記の浅い補充へ変えた。音声から実際の生理的呼吸を測定したデータではなく、休止に同期させた演技設計。

## 検証結果

- v8とcmo3・moc3・テクスチャ・表示情報のハッシュが一致。CSVの呼吸以外の全列と、motion3の呼吸以外の5曲線が完全一致。
- 増加する全フレームが採用休止内。吸気区間の実音声ピークは最大でも約-53.86dBFS。休止外の吸気上昇は0。
- 呼気区間は全て単調減少。吸気の平均速度0.334〜0.834/秒、呼気約0.11/秒。最大1フレーム変化0.041144、SDK呼吸再生誤差約0.000064。
- 2本とも全フレームデコード、フレーム数・寸法・fps・音声と映像の開始時刻および尺に合格。v8のAACを再圧縮せず流用し、デコードした音声PCMも完全一致。
- 単独版10時点のPNG照合誤差は最大1.121/255未満、比較版左右4時点は最大2.579/255未満。顔領域は同時刻v8のPNGと画素差0。
- 最大吸気の前後で胸領域の平均RGB差4.507/255を検出。曲線図、代表10時点、比較版の画像を目視し、明らかな首元・衣服の破綻は認めなかった。
- 自然さ、息継ぎの頻度、短い吸気の速さは最終通し視聴で評価する。技術検査をその代用としない。

検証スクリプトの初回実行で、subprocess引数に整数を渡したためTypeError。文字列へ修正して再実行し合格。動画の再生成やモデル修正を必要とする不具合ではなかった。

## 再生成と運用

プロジェクトルートから：

```powershell
output/live2d/runtime_venv/Scripts/python.exe output/live2d/speech_breath_v1/build_sample.py
output/live2d/runtime_venv/Scripts/python.exe output/live2d/speech_breath_v1/verify_sample.py
```

曲線だけは `--curve-only`、描画からは `--render-only`。入力はv8のモデル・CSV・音声・MP4と `voice_sync_v2/alignment/phonemes.json`。既存v8のRendererとmotion出力関数を利用する。検査にはv8のspeaking参照PNGが必要。設定の実装元はbuild_sample.pyのPROFILEで、breath_profile.jsonは実行時の記録。調整データの汎用性は別モデル・別音声で未検証。

担当は親Astra、子Agent0、forkなし。Highを候補とする設計作業として進めたが、実行中の推論強度の切替・実効値は確認できず、変更したとは扱わない。所要時間・契約使用量は未計測。既存動画・Filmora・元モデルは保持し、全編への適用は行っていない。
