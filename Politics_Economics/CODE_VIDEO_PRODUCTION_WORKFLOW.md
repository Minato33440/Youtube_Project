# 政治・経済系YouTube動画 — コード処理主体の制作Workflow

作成日：2026-09-10

切り抜き対象の利用条件は [公式チャンネル利用条件台帳](../docs/channel_rights_registry.md) で管理する。素材採用時にCH IDを各制作の`sources.md`へ記録し、公開前に公式条件・収益化条件・動画ごとの例外を確認する。

対象：AstraがPython/FFmpeg等で構成確認用MP4を生成し、Bossと構成を詰めた後、素材をFilmoraへ引き継ぐ制作経路。
この文書は手順と合意事項であり、以下の工程を実行済みとする制作報告ではない。

## 1. 既存Workflowとの区別

| 経路 | 主な編集方法 | この段階の成果物 |
| --- | --- | --- |
| 本Workflow | 編集内容をデータ化し、コードで切り抜き・配置・合成・書き出し | 構成確認用MP4、編集データ、個別素材、検証記録 |
| [ローカルエディター主体のWorkflow](VIDEO_PRODUCTION_WORKFLOW.md) | Computer-useによるFilmoraのタイムライン操作 | 編集可能なFilmoraプロジェクト、書き出しMP4 |

本Workflowはローカルのプロジェクト内で実行する。クラウドのサンドボックスへの移行を前提にしない。音声・画像の生成に外部サービスを使う場合は、ローカル編集とは分けて記録する。

制作全体ではFilmoraで再編集できる状態も残す。コードで生成した統合MP4を取り込むだけでは、音声・字幕・画像が個別レイヤーに戻らないため、引継ぎ用素材を保持する。

## 2. 今回のテスト動画の構成

Bossと合意した構成は次の3段階。

1. テーマの注目点を示す短い冒頭切り抜きの後、続きを見たくなる注目点をナレーションで伝え、本編へ進む。
2. 必要に応じて、各切り抜きの前にテーマに沿った短い解説を挿入する。
3. 本編の最後に分かりやすいまとめを入れ、当チャンネル紹介を軽く添える。紹介の文言は後で詰める。

以下の秒数・章分けはAstraの試作目安。固定の合意尺や視聴維持率の実証値ではない。

| 順序 | パート | 試作目安 | 役割 |
| --- | --- | --- | --- |
| 1 | 冒頭の注目発言 | 15〜25秒 | 中心となる疑問を1つ示す。前後の条件を失う切り方は避ける |
| 2 | 導入ナレーション | 20〜30秒 | 視聴者が何に注目し、何を理解できるかを伝える |
| 3 | 本編の切り抜き群 | 採用区間の実尺 | 発言と説明を順に見せる |
| 4 | 本編間の橋渡し | 必要箇所に10〜20秒 | 話題の転換、前提、用語を短く補う |
| 5 | まとめナレーション | 40〜60秒 | 冒頭の疑問に答え、要点を2〜3点に整理する |
| 6 | チャンネル紹介 | 仮枠5〜10秒 | 文言未確定。確定までは編集データ上の枠として保持する |

今回の出発点は既存の切り抜き7区間とナレーション3本。実ファイル、原稿、音声設定、既存タイムラインを照合してから再利用する。新構成に合わせてナレーションを追加・短縮・差し替えるため、本数は3本に固定しない。冒頭に本編の一部を再掲する場合は、同じ素材の別配置として記録し、重複分も総尺へ含める。

本編は素材の本数より論点のつながりを優先する。今回の仮のまとまりは「国債・財政への不安」「減税財源」「投資と暮らし」。7区間すべてに解説を挟む必要はない。自然につながる箇所はそのまま接続し、必要なら章見出しだけを使う。

導入と橋渡しで次の発言の答えをすべて先取りしない。まとめでは本編にない論点を増やしすぎず、出演者の主張とチャンネルの考察を区別する。未確定のチャンネル紹介を無断で完成原稿扱いにせず、確認版で省略した場合も制作メモに残す。

参考：[構成参考動画](https://www.youtube.com/watch?v=Z3tijCK-7kU)。2026-09-10に取得したチャプターと自動字幕では、0:00ダイジェスト、0:32管理人あらすじ、0:58本編、18:39管理人まとめ。これは構成の参考であり、映像・音声の通し視聴による評価、発言内容の事実確認、視聴維持効果の検証ではない。

## 3. 制作工程

### Step 1：制作メモと素材の確認

- `brief.md`にテーマ、対象視聴者、冒頭の疑問、最後に持ち帰る要点、合意事項、未確定事項を記録する。
- 既存のカット表・原稿・素材・タイムライン・検証記録を確認し、最新版と対応関係を特定する。古い原稿の記載だけで現状を判断しない。
- 素材の発信元、公開日と収録日、出典、利用条件を`sources.md`に記録する。
- 自動字幕は仮資料として扱い、話者・人名・数値・否定・成立条件・カット境界は原映像と音声で確認する。

成果物：制作メモ、出典一覧、再利用素材一覧、未確認事項。

### Step 2：構成と編集データの作成

- `cuts.csv`で元動画の採用区間と理由を管理する。既存形式は読み替え、必要な項目を補う。
- `code_edit/timeline.json`で、冒頭切り抜き、導入、本編、橋渡し、まとめ、紹介枠の配置を管理する。
- 各項目に安定したIDを付け、原稿、音声、画像、字幕、出典をIDで対応付ける。
- 構成判断の採用理由、退けた案、残る疑問は制作メモに保持する。

編集データに必要な情報：素材パス、種別、元素材の開始・終了、配置順、実測尺、完成動画の開始・終了、トラック、字幕・画像の表示区間、音量調整、出典ID、版番号。時刻の単位、フレームレート、終了時刻を含むかどうかも明記する。

完成動画の配置時刻は素材の実尺から計算する。未生成音声の仮尺を最終値として固定しない。ナレーションの尺が変わったら、後続の映像・字幕・画像も再計算する。

成果物：カット表、構成表、編集データ。

### Step 3：ナレーションと説明素材の準備

- 導入、必要な橋渡し、まとめを区別して原稿を作る。専門用語は初出時に短く説明する。
- 根拠のある事実、出演者の主張、編集者の解釈を分け、曖昧な断定を原資料へ戻って確認する。
- 既存音声の再利用を優先し、変更部分を必要に応じて生成する。採用済みの声と読み設定を確認し、勝手に別の声へ変更しない。
- 音声合成は利用可能なエンジン/API/既存音声で行う。Python/FFmpegだけで指定音声を新規生成できるとは扱わない。エディター固有の音声生成が必要なら、その工程だけを外部依存として記録する。
- 音声ごとに原稿版、エンジン、話者、速度、読み、実測尺を記録し、人名・専門語・間・文末を試聴する。
- 説明図や背景を用意し、日本語の文字・数値を編集可能な形で保持する。グラフは確認済みのデータから作る。

成果物：原稿、ナレーション音声、説明素材、生成設定と出典。

### Step 4：コードによる切り抜き・合成

1. FFprobeで入力の尺、映像・音声ストリーム、解像度、フレームレート、サンプルレートを確認する。
2. カット表から採用区間を切り出す。精密な境界が必要な場合は再エンコード等で時刻を合わせ、キーフレーム依存のずれを確認する。
3. 出力の映像・音声仕様を決め、素材を統一する。今回の初期候補は1920×1080・30fps・H.264/AAC。実素材との整合を確認して編集データに固定する。
4. 音声の実尺に合わせて背景・画像・字幕を配置し、編集データから順に合成する。
5. 完成タイムライン用のSRTを生成する。元動画字幕の時刻をそのまま流用せず、切り出し位置と配置位置で変換する。
6. 音量差やピークを測定して調整し、試聴で確認する。既定でBGMや効果音を増やさない。
7. 新しい版の確認用MP4を書き出す。過去の確認版やFilmora書き出しを上書きしない。

既存の処理を再利用し、入力・編集設定に変更がない中間素材は再生成を避ける。再利用の判定には入力と設定の版やハッシュを使い、ファイルが存在するだけで最新とみなさない。

成果物：個別カット、合成スクリプト、編集設定、確認用MP4、実行ログ。

### Step 5：技術検証と内容確認

| 確認 | 方法・判定 |
| --- | --- |
| 出力形式と尺 | FFprobeの結果を編集データと比較する。許容差は出力fps等から決める |
| デコード | 全編をデコードし、エラーを検査する |
| 配置 | 全パートの順序・実尺・開始終了を照合し、意図しない空白・重複を調べる |
| 音声 | 全音声パートの存在、無音・ピーク・音量差を検査し、接続部を試聴する。検出だけで欠陥と断定しない |
| 字幕・画像 | 時刻・文字切れ・重なり・表示時間を検査し、代表フレームと接続部を確認する |
| 発言の意味 | 冒頭の抜粋と全カット境界を前後の文脈と照合する |
| 視聴の流れ | 冒頭の問い、本編のつながり、解説の重複、まとめでの回収を映像・音声で確認する |

`test_report.md`には自動検査、映像確認、試聴、Bossによる通し確認を分けて記録する。確認者、対象版、確認区間、未確認区間、欠陥と修正を残し、フレーム抽出や部分試聴を全編視聴と報告しない。

技術検査の合格だけで内容の分かりやすさや公開準備の完了とはしない。実行環境で映像・音声の確認ができない場合は、該当箇所を未確認として明示する。

### Step 6：Bossと構成を詰め、再生成

確認用MP4を提示し、「どこで話を見失うか」「説明が長い・重複するか」「冒頭の問いに答えているか」を中心に確認する。
修正は対象版とタイムコードに結び付け、原稿・カット表・編集データへ反映して次の版を生成する。変更箇所と影響する接続部を再検証する。

合意済みの方針内の修正で繰り返し許可を求めない。テーマや解釈を大きく変える判断はBossとすり合わせる。チャンネル紹介の未確定は、他の構成確認を止める理由にしない。

成果物：構成が固まった確認版、変更記録、Filmoraへの引継ぎ対象版。

### Step 7：Filmoraへ引き継ぐ

引継ぎ時は次を揃え、[ローカルエディター主体のWorkflow](VIDEO_PRODUCTION_WORKFLOW.md)の素材配置・統合編集・保存・再読込・書き出し工程へ移る。

- 承認対象の確認用MP4と版番号。
- 個別の切り抜き、ナレーション、背景・説明画像、字幕SRT。
- 出典、元動画の開始・終了、完成動画の配置時刻、トラックと音量の一覧。
- フォント・字幕スタイル・映像音声仕様、未確定事項、検証済み範囲。

素材は安定した場所へ保持し、一覧はプロジェクト基準の相対パスと解決済みパスを対応付ける。実体の複製が必要でなければ大容量ファイルを二重保存しない。
JSON/CSVをFilmoraがそのまま読み込めるとは仮定しない。配置一覧に沿って個別素材をトラックへ置き、再編集可能なプロジェクトを保存・再読込して検証する。GUI操作は同時に1担当のみ。

## 4. 保存先と版管理

既存の動画フォルダーを使い、原素材と旧成果物を保持する。次は今後作る成果物の推奨配置であり、実装済みファイルの一覧ではない。

```text
YYYY-MM-DD_テーマ名/
  brief.md
  sources.md
  cuts.csv
  narration.md
  code_edit/
    timeline.json             # 再生成の編集データ
    render.py                 # 既存スクリプト再利用・参照でもよい
    render_settings.json
    changes.md
  media/                      # 元動画、個別カット、音声、画像
  subtitles/                  # 素材用・完成タイムライン用を区別
  exports/
    code_review_vNN.mp4
  filmora/
  handoff/
    asset_manifest.csv        # 素材と配置・出典の対応
    README.md                 # 対象版、取り込み手順、未確定事項
  test_report.md
```

既存の`speech/`や`work/`等は無理に移動せず対応表で参照する。Gitには原稿・字幕・編集データ・スクリプト・記録を残し、動画・音声・画像・Filmoraプロジェクトは既存の除外方針に従う。認証情報や期限付きの認証URLは追跡ファイルへ含めない。

## 5. 推論・Agentと完了条件

配分の正本は [AGENTS.md](../AGENTS.md)。通常制作はAstra Mediumを開始点とし、難しい文脈や整合性判断ではHigh以上を検討する。小規模・直列作業は子Agentなし、独立作業に実益があればLuna/Terra/Solを担当範囲に応じて使う。履歴は必要最小限とし、根拠・合意・反証を落とさない。

モデルと推論の指定値・観測値、子Agent数、引継ぎ範囲、所要時間、手戻り、欠陥、確認負担を記録する。短い履歴や下位モデルによる節約は品質と実測を伴って評価し、検証を省く理由にしない。

本Workflowの構成確認版が完了したと言える条件は、合意した構成を反映したMP4、再生成可能な編集データ、個別素材、出典、検証記録が揃い、未確定事項が明示されていること。Filmoraへの引継ぎ後は、編集可能なプロジェクトの保存・再読込も制作全体の完了条件に含める。
YouTubeへのアップロード・公開はこのWorkflowの実行に含めず、Bossの別途指示に基づいて行う。
