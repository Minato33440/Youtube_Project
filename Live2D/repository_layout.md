# YouTubeとLive2Dの配置・分離方針

更新: 2026-09-19。今回の判断：**当面は同一リポ内で制作領域を分け、既存素材の移動を伴うリポ分割は後にする。**

## 判断理由と確認した依存関係

事業としてはTommy’s WorksとYouTubeを分ける。一方、現在のリサは共通技術の参照実装でもあり、動画試作と同時に育ってきた。

| 現状の根拠 | 分割時に必要になる対応 |
| --- | --- |
| `work/build_risa_filmora.py`が`Politics_Economics/2026-09-09_fiscal_policy`を参照 | 動画側とモデル側の受渡しを定義する |
| `output/live2d/punctuation_pause_v1/build_sample.py`が`chest_breath_v8`の処理と`speech_breath_v1`を参照 | 最新フォルダだけの移動では再生成できないため依存を追う |
| `Live2D/presets/risa_reference_v1.json`にリポ絶対パスと動画配置値がある | 共通設定・リサ固有・動画固有の値を分ける |
| `Risa_speech_breath.model3.json`が親のモーションと音声を参照 | modelフォルダだけでは単独配布一式にならない |
| PSD・画像・音声・動画・Filmoraファイル等がGit除外 | リポ分割／cloneだけでは実体がそろわない。素材の復元手順が必要 |

今の分割は、二重管理・パス修正・素材不足への対応を先に増やす。まずリサの動作を再利用し、レン本体を作る今回の優先順位には、文書と新規制作の境界を先に整える方が合っている。

## 当面の配置

```text
Youtube_Project/
├─ Politics_Economics/       YouTubeの企画・原稿・映像編集
├─ Live2D/
│  ├─ README.md             Live2D全体とリサ既存成果物への入口
│  ├─ presets/              暫定共通設定・人間型初期値・リサ参照値
│  ├─ model-ren-asagiri/     レンの商品仕様・実装計画（今後、原画・モデル）
│  ├─ future/               本体完成後のAI連携商品構想
│  └─ repository_layout.md  この配置判断
├─ docs/live2d_business/     旧事業提案と現在の制作入口
├─ Grok/                    外部セッションの原資料
├─ output/live2d/           リサの既存試作・生成処理・検証・入力
└─ work/                    既存の動画／モデル連携用補助処理
```

既存の`Live2D/model-ren-asagiri/`は空だったため、今回そこを制作入口にした。原画やモデルの二重コピーは作っていない。`output/live2d/`は名前だけで再生成可能なキャッシュと判断せず、編集用モデル・入力・検証記録を含む制作資産として扱う。

新規レン作業は専用フォルダへ集める。共通プリセットはキャラクター固有調整で上書きせず、適用版と差分を記録する。リサを別キャラクター階層へ移すのは参照修正と再現試験を含む別の作業とする。

## 将来、独立リポへ切り出す目安

- Live2Dの制作・販売リリースが動画更新と独立して増えてきた。
- リサ／レンのモデルと必要素材を一式で取り出し、別の作業場所で読み込み・再生成できる。
- 共通コード・設定と、YouTube固有の音声・配置・カット情報を分けられた。
- 素材の保管、バックアップ、復元方法が決まり、協力者や公開範囲を分ける必要が出た。

分離する場合は、Live2D側が編集原本・共通処理・モデル商品を管理し、YouTube側はバージョン固定した配布用モデルを利用する構成を推奨する。別リポの制作途中ファイルを直接参照する運用は避ける。リポ名は未決定。

移行時は、参照一覧と素材ハッシュを作る→復元可能なバックアップ→新配置のコピーで保存・再生・動画合成を確認→リンクを切り替える、の順で進める。既存履歴を保持し、確認前に旧実体を削除しない。Git LFSまたは外部素材保管の選択もその時に実サイズと運用から決める。

## 今回実施したこと・検証範囲

リポ構成、該当文書、Git状態、代表的な処理・モデル参照を読み、制作資料を追加し入口を更新した。網羅的な全依存監査ではない。Gitリポ作成、素材移動、既存モデル変更、Cubism操作、動画生成、出品は行っていない。

検証結果：対象10文書のローカルリンク97件は参照先が存在し、`git diff --check`も問題なし。初回のリンク検査は既存の山括弧付き絶対パスを誤判定したため、検査側のパス解釈を直して再確認した。アプリ動作・販売品質の検証とは区別する。

担当：親エージェント、子Agent 0。モデル・推論強度の実効値、使用量、正確な所要時間は未取得。通常の資料整理として実施。
