# キャラクター制作ワークフロー v2.2

更新：2026-09-27。リサのパーツ制作・PSD検証・段階的な動作確認を、レンでの原画再現とBossとの分業、さらにCubism教材化セッションで整理した「PNG原画→コード分離→Photoshop修正→Cubism Import」と、ArtMesh／Deformer／参照原画の役割分担を踏まえて更新した現行手順。

**Cubismへ入れる前に、可動単位ごとの見た目・隠れ部分・重なりを完成させ、その採用版をPSDへ組み、Cubismで動きを一段ずつ追加する。** 自動化するのは初期分離・配置・組立・比較・検査を中心とし、原画らしさの判断と細かな作画はBossとすり合わせる。

新規キャラでは、原則として **PNG原画作成 → コード分離PSD化 → Photoshopでパーツ修正・塗り広げ → 修正済Material Master.psd（= Cubism Import PSD）→ Cubism Import** を標準ラインとする。

対象は原画準備から瞬き・会話口・顎首連動・小さな頭部傾斜・髪揺れの初期確認まで。横向き・うなずき以降は次工程。販売完成、全角度の破綻解消、配信アプリ対応まで完了した手順とは扱わない。

## 2. BossとAgentの分業・受け渡し

レンの品質向上は、Bossが原画に忠実な各パーツを手作業で作り込み、Agentが合成・比較と実装を反復した共同制作の結果。自動生成やコードだけで完成したものとして記録しない。

| 工程 | Bossが主に担当したこと | Agentが主に担当したこと | 受け渡すもの |
| --- | --- | --- | --- |
| 原画 | キャラの体格・顔つき・色・アホ毛を選定し、前後原画と補助原画を用意 | 動作に必要な分割や補助素材を提示 | 採用原画、左右の定義、目標の動き |
| パーツ補修 | 手動透過、線の復元、髪のパス、耳のゴミ取り、顔の輪郭・鼻筋の陰影、眉・目周辺・虹彩、口の塗り直し | 初期分割、口内の分離、重ね合わせ、欠け・隙間・寸法変化の指摘 | 修正PNGと変更内容、配置見本 |
| 隠れる部分 | 首の顎下／胸元延長、襟・裏地、髪の根元と後ろ髪の延長 | 必要範囲を測定し、重ねた状態で確認 | 接続を覆えるPNG、局所比較 |
| 見た目の確定 | 原画との雰囲気の一致を判断し、必要箇所を再修正 | 同倍率の原画比較、髪・耳込みの頭部合成、開閉試作を作成 | 採用合成と入力一覧 |
| PSD・Cubism | サンプルの自然さを評価し、会話口の大きさや歯の見え方等を指示 | PSD組立・検査、メッシュ・キー形状・連動・物理・実モデル描画 | 編集モデル、動画、検査結果 |

修正依頼は「対象ファイル・見える問題・画像上の位置・必要な塗り足し／保持したい線」を具体化する。Bossの修正受領後は内容を読み直し、同じ欠陥を旧画像から再指摘しない。Agentが修正する範囲はその時の依頼に合わせる。

レン既存工程の反復単位は **修正PNG → 配置更新 → 原画との比較 → Bossの判断 → 採用記録**。新規キャラでは初期コード分離後、修正の正本をMaterial Master PSDへ寄せ、**PSD内のパーツ修正 → 全体重ね合わせ確認 → Bossの判断 → 採用記録** を基本とする。静止時の採用を、そのまま動作時の合格に繰り上げない。

## 3. 素材の管理と作業開始

1. キャラのREADMEから現行素材・モデル・検査対象を確認し、作業前のファイルハッシュと変更状態を残す。保存中・未保存のEditor作業がある場合も確認する。
2. 原画は保存用の入力として維持する。加工済みPNG、配置情報、派生PSD、リグ、runtime、プレビューを区別する。
3. 現行フォルダーは番号・日付なしの固定入口を基本にする。旧版は`archive/日付-理由/`へ退避し、移動元・移動先・ハッシュを記録する。既存の参照を壊す一括改名はしない。
4. レン既存工程では修正を現行フォルダーの同名PNGへ反映した。新規キャラでは、コード分離後のMaterial Master PSDを作画修正の正本とし、各可動パーツのレイヤーへ修正を反映する。採用版はREADME／manifestで明示し、最大番号や更新時刻だけで決めない。ユーザーの新しい保存先指定を優先する。
5. `facial_feature.png`等の配置見本は位置の参考。見本や旧PSDの埋込画像より、指定された個別PNGを優先する。
6. ファイル名のL/Rだけで左右を推定しない。画面左／右、キャラ左／右、色を対応表にする。レンは画面左＝キャラ右＝茶、画面右＝キャラ左＝青。旧`Upper_eyelid`が眉として使われた例もあり、役割を確認する。

新キャラで残す最小情報は[制作記録テンプレート](templates/character_production_record.md)を使用。フォルダーを大量に先行作成する必要はない。レンの既存身体素材は`processing_v001`が現行という例外をREADMEで明示している。

## 4. 原画・補助素材の準備

- 顔つき・体格・画角を決めた前面原画を基準にする。背面は後頭部・衣装の設計資料として使い、前後が揃っただけで横向きモデルが完成するとは考えない。
- 解像度は幅×高さで記録する。レンは4000×6000px。高解像度の原本は保持し、比較用縮小画像やプレビュー用アトラスと区別する。
- 髪なしの頭部・耳、歯と口内の見える画像は補助として有用。顔が画素単位で一致しない笑顔原画は口周辺だけを取り、基準顔へ局所的に合わせる。
- 通常会話・大笑い・大きな首振りなど、作る範囲を先に区別する。全表情の上半身原画を必須にはしない。

完了条件：基準原画が一意で、補助素材の用途と一致しない箇所が説明できる。

## 5. PNGを分割・補修する

矩形ゾーンの切り出しと背景色の除去は初期素材にすぎない。動かす単位ごとに輪郭を整え、背後へ隠れる部分を補う。

| 部位 | 分割と描き足し | 確認すること |
| --- | --- | --- |
| 顔下地 | 頭部〜顎の輪郭、肌、鼻、頬・鼻筋の陰影。独立させる目・眉・口の残りを除く | 顎の欠け、余計な線、二重輪郭、色の継ぎ目。`face_surface`を役割なく二重に重ねない |
| 目 | 左右の白目、虹彩、上まつ毛、下まぶた、眉、必要な補助線と閉眼線 | 原画の開口形、虹彩の比率・大きさ・位置、目尻。眼窩／鼻筋の線をまつ毛に重ねない |
| 口 | 閉口線、口内、上歯、舌、上下口縁 | 元の口内に歯・舌が焼き付いたまま別パーツを重ねない。下歯は必要時のみ追加 |
| 髪・耳 | アホ毛、前髪の束、横髪、後ろ髪、左右耳 | 根元・耳との重なり、動かして露出する下地、耳外縁の残り。髪束同士の線を削らない |
| 首・服 | 顎下へ伸びる首、襟下へ伸びる胸元、左右襟、裏地、胴体シャツ | 首に残る旧顎線を除き、襟開口部を肌で覆う。シャツの切り抜きと裏地の重ね順 |
| 四肢 | 必要な動作に応じ腕・手・脚・靴 | 付け根の重なりと袖口。指の細分化は必要な動きを決めてから |

背景抜きは黒い輪郭と半透明の縁を残す。自動選択で輪郭まで消えた箇所は、削り続けず元絵・バックアップから戻し、拡大したパス／多角形選択／マスク等で局所修正する。暗色・明色・透過チェック背景で、白縁、ベージュ残り、指の間、アホ毛、靴底を確認する。

原画再現では一律の「理想的な虹彩比率」へ直さない。レンではBossが原画に合わせ、縮小後に縦へ延ばした虹彩を採用した。目的はキャラ固有の印象を保つこと。

## 6. 配置・比較・PNG完成登録

1. 元キャンバスの左上を原点とする座標、PNG寸法、反転・倍率、重ね順、表示状態を保存する。縮小プレビューの座標を原寸へ混ぜない。
2. 余白追加やトリミングで寸法が変わったら、絵柄の基準点で再配置する。ファイル左上が同じでも目や輪郭の位置が保たれるとは限らない。
3. 個別PNGだけから全身／頭部／目・口・首の局所合成を作る。髪なしで顔を確認した後、髪・耳を重ねて最終的な印象も見る。
4. 原画と同じ範囲・同じ倍率の左右比較と、必要な重ね合わせを作る。単体パーツ一覧だけでは配置の良否を判断しない。
5. 開眼・半開眼・閉眼、閉口・小・中・会話最大の試作を確認する。PNG段階のGIFは形状検討用であり、Cubism動作確認とは区別する。
6. 採用したPNG一覧・SHA256・寸法・配置・合成サンプル・Bossの判断を登録する。差し替えがあれば再合成し、古い完成サンプルを残したまま採用情報だけ更新しない。

完了条件：原画に対する顔の印象が了承され、通常表示の欠け・ゴミ・継ぎ目が解消し、動作用の隠れ部分が用意されている。大角度での余白はリグで別途検査する。

## 7. PNG原画からMaterial Master／Cubism Import PSDへ

### 7.1 このプロジェクトでの定義

新規キャラでは、**Photoshop Material Master.psd = Cubism Import PSD** として扱ってよい。条件は、Cubismで1つの可動単位として扱う各パーツが、Photoshop上ですでに1枚の独立レイヤーへ統合されていること。

たとえば前髪中央をCubismで1 ArtMeshとして扱うなら、線・ベース色・影・ハイライト・局所修正をPhotoshop上で仕上げた後、`hair_front_C` の1レイヤーとして保持する。全パーツを1枚へ統合するのではなく、**1可動パーツ = 1レイヤー** を維持する。

編集途中で線画・影・マスク等を複数レイヤーのまま保持したい場合だけ、編集用Material MasterとCubism Import PSDを分ける。その場合も、Cubismへ渡す側では各可動パーツを1レイヤーへまとめる。

### 7.2 新規キャラの標準ライン

```text
PNG原画作成
    ↓
コードで初期パーツ分離・配置
    ↓
Photoshop Material Master.psd を生成
    ↓
Astra / Agent と欠損・隙間・塗り広げ必要箇所を確認
    ↓
BossがPhotoshopで各パーツを修正・描き足し・塗り広げ
    ↓
全パーツを元キャンバス位置のまま重ね合わせて静止品質を確認
    ↓
修正済 Material Master.psd = Cubism Import PSD
    ↓
独立読戻し・manifest・比較検査
    ↓
Cubism Import
```

この流れでは、Cubismへ入ってから絵そのものを直す手戻りを減らす。Cubismでは主にメッシュ・デフォーマ・パラメータ・キー形状・物理を扱い、素材品質の不足が見つかった場合だけPSDへ戻る。

### 7.3 コード分離とPhotoshop修正の役割

- **コード／Agent**：矩形抽出、背景除去、初期座標、レイヤー生成、重ね順、manifest、合成比較、ハッシュ検査など、数値で再現できる処理を担当する。
- **Boss／Photoshop**：輪郭、髪の線、耳外縁、目・眉・虹彩、口、肌陰影、首・胸元・髪根元などの隠れ部分、塗り広げを最終判断する。
- **Astra / Agentとのレビュー**：各パーツ単体だけでなく、全身・頭部・目口・首襟などを重ねた状態で、隙間・ゴミ・二重線・露出不足を特定する。

コード分離は完成作画ではなく**高再現性の初期分離**と位置づける。人間がPhotoshop上で各パーツを直接見ながら修正することで、個別PNGを往復するより接続部・重なり・塗り広げを把握しやすくする。

### 7.4 Material Master／Import PSDの作成条件

1. 元キャンバスの左上を原点とする座標、PNG寸法、反転・倍率、重ね順、表示状態を保存する。縮小プレビューの座標を原寸へ混ぜない。
2. 各パーツは元のキャラクター位置を維持する。パーツ一覧用のように別位置へ並べ直さない。
3. RGB 8bit、透過背景、元キャンバス寸法、独立した一意のレイヤー名で保存する。
4. Cubismで同一可動単位として扱う線・色・影等は、Photoshop修正完了時点で1レイヤーへ統合する。
5. 顔・目・髪・耳・口・首・襟・衣装等を全体重ね合わせで確認し、静止状態の欠け・隙間・ゴミ・継ぎ目を解消する。
6. 動かしたときに露出する首の顎下、胸元、襟裏、髪根元、後ろ髪等の隠れ部分を必要範囲まで塗り広げる。
7. 採用manifestの各ファイル／レイヤーを読み、ハッシュ・寸法・左右を照合する。予想外の更新があれば差分を先に確認する。
8. 保存したPSDを読み戻し、層数・名前・順序・位置・可視状態・RGBAを検査する。別系統の読込でレイヤーから強制再合成し、保存済み統合プレビューだけを見て合格にしない。
9. 大きいキャンバスは帯状に分割して検査し、メモリ負荷を抑える。レンの検査例は最大表示差1.683/255未満、差2超0。新しい環境では許容差の根拠を確認する。
10. 原画比較とPSD読戻し画像を目視し、入力素材のハッシュが処理前後で意図せず変わっていないことを確認する。

実行例は共有ツールREADME、レン固有の配置と検査は[psd_front](model-ren-asagiri/art/psd_front/README.md)を参照。`prepare.py`等にはレン固有の座標・枚数・ファイル名があるため、新キャラへ無変更で実行しない。古い初期分割コードを再実行して手修正済みMaterial Masterを上書きしない。

完了条件：**1可動パーツ = 1独立レイヤー** が成立し、原画の印象、通常表示の接続、動作用の隠れ部分、PSDの独立読戻しがすべて確認でき、どの初期分離素材から作ったPSDか追跡できる。

## 8. Cubism取り込み・初期メッシュ

1. Editorのバージョン／利用状態と読込PSDを記録し、読み込み直後を別名で保存する。既存リグを静止PSDから作り直して上書きしない。
2. 初期表示、全身座標、非表示の表情補助、描画順、左右をPNG合成と比較する。足りない表情素材を追加PSD経由で組み込んだ場合も出典を残す。
3. 変形させる目・口・顎・髪の輪郭に合わせてメッシュを確認する。自動メッシュ生成だけで瞬きや口形の完成とはしない。
4. パーツを階層化し、目・眉・耳・口内・閉眼線まで頭部に追従させる。原画の中立形状を基準キーとして保持する。
5. テクスチャを配置し、対応するSDK形式でruntimeを書き出して実際に読み込む。元PNGの解像度とアトラスの解像度は別に記録する。
6. cmo3を閉じて再読込し、保存された状態を確認する。

レンの観測環境はEditor 5.3.04 FREE、確認用2048アトラス1枚、SDK5.0書出し／ローカルCore5.1。SDK5.3書出しではローカル再生に失敗したため互換形式を選んだ。これは当該環境の実績であり、今後の版の一般的な制限とはしない。新しい機能・版・ライセンスが必要になった時点で確認する。

### 8.1 ArtMesh・Deformer・参照原画の役割分担

Cubism教材 Lesson 02 では、PSD Import直後の各パーツがArtMeshとして生成されても、初期Meshは四隅4頂点＋対角線の最小構成であり、変形に適した実用Meshが自動的に完成しているわけではないことを確認した。

ArtMesh／Mesh／Deformerの役割は次のように分ける。

- **ArtMesh**：1可動パーツの画像と、その局所変形を受け持つ単位。
- **Mesh**：ArtMesh内部の頂点・辺・三角形。顎、頬、毛先など局所的な形状変化を表現する。
- **Warp / Rotation Deformer**：複数ArtMeshをまとめて動かす階層。頭部全体の傾き、向き、位置変化など大きな姿勢変化を優先して担当する。
- **Parameter / Keyform**：変形の軸と、その軸上での状態を定義する。中立から端点までの中間値はCubismが補間する。

Meshは細かいほど良いとは限らない。必要な変形を表現できる最小限の密度を基本とし、パーツの用途に合わせる。顔輪郭や髪束には局所変形に必要な頂点を持たせる一方、虹彩のように主に平行移動するパーツでは過剰な細分化を避ける。

### 8.2 変形設計の優先順位

大きな姿勢変化をArtMeshだけで作ろうとせず、まずDeformerで全体構造を作る。ArtMesh補正は、その結果を見たうえで残る局所差に限定する。

基本順序：

```text
中立姿勢
    ↓
軸ごとのDeformerで大きな姿勢変化を作る
    ↓
Parameterを中間値まで動かして補間を確認
    ↓
必要な局所だけArtMesh / Meshを補正
    ↓
複数軸を組み合わせて再確認
```

頭部の例では、横向き（AngleX）、うなずき（AngleY）、横傾き（AngleZ）を別軸として扱う。複数の動きが混じった参照原画を、1軸の端点として丸ごとトレースしない。

### 8.3 参照原画は「正解輪郭」ではなく「演技のガイド」

変形終点の参照原画は、Meshを完全一致させるためのトレース画像とは扱わない。顎先、鼻、耳下、首接続、前髪位置などの**方向・距離・特徴点の目安**として使用する。

終点でArtMeshを補正すること自体は許容する。中立と端点の間はCubismが補間するため、端点補正が即座に破綻を意味するわけではない。ただし、評価の優先順位は次の通りとする。

1. 中立姿勢で原画の印象が保たれている
2. 中立 → 中間 → 終点が連続して自然に見える
3. 複数Parameterを重ねても顔・首・髪の接続が破綻しない
4. 終点が参照原画の意図・雰囲気を保っている
5. 参照原画との輪郭の完全一致

したがって、**静止原画の完全一致より、キャラクターらしい自然な連続変形を優先する。** 参照原画は「唯一の正解画像」ではなく、演技の方向を示す検証基準とする。

### 8.4 中間姿勢の確認

端点だけで合格にしない。Parameterスライダーを中立から端点まで連続的に動かし、少なくとも中間域を確認する。必要に応じてCubismのランダムポーズ、複数軸の組合せ確認、四隅のフォーム生成等を使い、目測だけで全組合せを手作業確認する負荷を減らす。

中間で不自然さが出た場合の修正順は、**Deformer構造 → Keyform配置／補間 → 局所ArtMesh補正** を基本とする。終点輪郭への一致だけを目的にMesh全体を作り直さない。

## 9. 瞬き → 会話口 → 顎・首 → 髪の順で実装

| 段階 | 実装 | 比較する状態・合格条件 |
| --- | --- | --- |
| 瞬き | 白目に虹彩をクリップし、上下まぶたで開口形を作る。必要なら開眼用と閉眼用まつ毛を変形・不透明度で切替 | 開き1／.75／.5／.25／0と左右独立。開眼の印象維持、中間の二重線・白目漏れ・急な切替なし |
| 会話口 | 閉口線、口内、歯、舌、上下口縁を連動。歯・舌を口内へクリップ | 閉・小・中・最大。口中心が下がりすぎず、中開きでも上歯が自然に見える。最大は通常会話に必要な範囲 |
| 顎・首 | 開口へ顎下地を控えめに追従。頭部傾斜へ首上部を追従し、襟内の下部を保つ | 口だけ低く見える問題は口の配置も確認。中立、左右傾斜、各開口との組合せで顎・耳下・襟に隙間なし |

## 10. 実モデルの動作確認と受入

各段階で、前工程の了承済みモデルを保持して比較する。

- **静止状態**：中立、各軸の端点と中間、片目閉じ、開口、髪の両端、顔傾斜＋瞬き／口を確認。局所拡大と全身を両方残す。
- **連続動作**：runtimeから10〜15秒程度の動画を描画し、瞬き・会話・傾斜・髪の収束を確認。実物理の確認では髪パラメータを直接振動させず、入力と出力を記録する。
- **機械検査**：素材ハッシュ、モデル参照、パラメータ、動画のデコード・寸法・fps・枚数・尺、必要な不変領域を確認する。
- **目視**：目尻・口角・顎・耳・首・襟・髪根元の欠け、跳ね、追従漏れ、線の二重化、原画からの印象のずれを見る。検出数0だけでは自然さの証明にならない。
- **Bossの受入**：対象動画／比較画像と判断日、評価、残る工程を記録する。PNG完成、PSD検査PASS、Cubism保存確認、動作了承、販売完成は別の状態として管理する。

色・階調はMP4を優先し、GIFは確認の手軽さに使う。共通パレットと実尺を確認する。レンではGIFのフレーム時間丸めで12秒が10.8秒になったため出力経路を修正した。

Editor保存後にcmo3が変われば、それ以前のruntimeと同じ内容とは断定しない。新しいcmo3を保持して差分を確認し、必要な書出し・再検査を行って対応を回復する。プレビューだけを見て編集モデルの同一性を保証しない。

## Lesson 07：複数Parameterの組み合わせ（完了まとめ）

### 目的
単一Parameterごとの変形確認から一歩進めて、  
**複数Parameterを同時に組み合わせた時でも破綻しにくい表情変化を作れるようになること**を目的として実施した。

今回の主な確認対象は以下。

- `Angle Z`（顔の傾き）
- `Eye Blink`（左右個別の開閉）
- `Smile`（左右個別の笑顔）
- `Mouth Open`
- `Mouth Form`

---

### 今回行ったこと

#### 1. 目の開閉を複数Keyformで構築
左右の目それぞれについて、  
`Eye Blink` を **5点キー** で設定し、中間地点も含めて変化を作成した。

- 0.0 = 閉眼
- 0.25
- 0.5
- 0.75
- 1.0 = 開眼

進め方としては、

1. 目全体を扱うDeformerで大まかな閉眼変形を入れる  
2. その後、各Art-Mesh（上まぶた、下まぶた、白目、虹彩、まつ毛など）を個別調整する  

という手順を確認した。

---

#### 2. Face Rotation配下での連動確認
`Face_Rotation_Practice` 配下に

- `Left_Eye`
- `Right_Eye`
- `Mouth`

などのグループやDeformerを整理し、  
顔全体の傾きに対して各表情パーツがどう重なるかを確認した。

この過程で、

- 単独Parameterでは自然でも
- 複合時には印象が変わる

ことを確認できた。

---

#### 3. 目の笑顔（Smile）を追加
左右の目に対して `Smile` Parameter を追加し、  
通常の閉眼とは異なる**笑顔用の目の細め方**を作成した。

特に学べた点は、

- `Eye Blink` は「閉じる動き」
- `Smile` は「笑顔として細める動き」

であり、似ていても目的が違うため、  
**別Parameterとして分けて作る意味が大きい**ということ。

---

#### 4. 口の変形と口開閉の組み合わせ
口については以下を組み合わせて確認した。

- `Mouth Open`
- `Mouth Form`

`Mouth Form` は **-1 / 0 / +1** を基本軸として使い、

- `+1` = 笑い寄り
- `0` = 中立
- `-1` = 不満・不機嫌寄り

という方向で作成した。

さらに `Mouth Open` を重ねることで、  
「閉じた状態の表情」だけでなく  
**発声・会話中の表情変化**まで確認した。

---

#### 5. 「不満口（Mouth Form -1）」を5点化して改善
初期状態では `Mouth Form -1` 側の変化がやや弱く、  
開口と組み合わさった時に印象が曖昧になりやすかった。

そのため、`Mouth Form -1` 側のキーフォームを増やし、  
**5点キー相当の段階変化**として各中間地点を微調整した。

これにより、

- 「笑い +1」と対になる
- 「不満・軽い不機嫌・軽い抗議」寄りの口

として、変化の方向性が分かりやすくなった。

---

### 今回の重要な学び

#### 1. 複数Parameterでは「単独で正しい形」がそのまま正解ではない
単体で見た時に良く見える変形でも、  
他のParameterと重ねると違和感が出る場合がある。

そのため、表情作成では

- 単独状態
- 中間状態
- 複合状態

をそれぞれ確認する必要がある。

---

#### 2. まずDeformerで大まかな方向を作り、最後にArt-Meshで詰める
今回のトレーニングで再確認できたのは、

- **Deformer** = 表情全体の方向づけ
- **Art-Mesh** = 各パーツの見え方の最終調整

という役割分担。

特に目や口のような細かいパーツでは、  
中間地点ほどArt-Meshの微調整が効いてくる。

---

#### 3. 中間地点の質が表情の自然さを決める
終点だけ作っても、途中の変化が不自然だと違和感が出る。

今回のトレーニングでは、  
**中間地点ごとの微調整が、そのまま自然なアニメーション品質につながる**  
という感覚を掴めた。

---

#### 4. 感情Parameterは「役割」を分けると整理しやすい
今回扱った中でも、

- `Eye Blink` = まぶたの開閉
- `Smile` = 感情としての笑顔
- `Mouth Open` = 発声量
- `Mouth Form` = 口の感情方向

というように、  
**Parameterごとに役割を分けると作業意図が明確になる**。

---

### 今回の作業方針として有効だった流れ

1. Parameterを作成する  
2. Keyformの点数を決める  
3. Deformerで大きな変化を入れる  
4. 中間地点を確認する  
5. 必要に応じて各Art-Meshを個別補正する  
6. 他Parameterと重ねて破綻チェックする  
7. 印象が弱い側はキー数を増やして補強する  

---

### 現時点で得られた感覚
今回のLesson 07を通して、以下の感覚がかなり掴めてきた。

- 各Deformerごとの役割の違い
- Keyformをどこに追加すべきかの判断
- 中間地点をArt-Meshで詰める意味
- 複数Parameterを重ねた時の破綻確認の見方
- 単なる「形合わせ」ではなく、表情の方向性を作る意識

---

### 現段階での結論
トレーニング段階としては十分な成果があり、  
**「複数Parameterを組み合わせた時の変形設計」と「中間地点の微調整」の基礎感覚を掴めた**。

特に今回は、

- 目の開閉
- 笑顔
- 口の開閉
- 口形状の感情差
- 顔傾きとの重なり

を実際に組み合わせて確認できたため、  
以後の本制作で必要になる表情設計の土台として有効だった。

---

### 次に活かす指針
今後の本制作では、以下を基本指針とする。

- **終点だけでなく中間地点を見る**
- **まずDeformer、最後にArt-Mesh**
- **感情Parameterと動作Parameterを混同しない**
- **複合状態を前提に形を作る**
- **印象が弱い側はキーを増やして段階補正する**
