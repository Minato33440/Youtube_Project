# レン — 中立正面の基本動作とXYZの土台作り

更新：2026-09-29。今回の対話を整理した実装計画。モデルへの反映は未実施。

## 1. 今回の進め方

先に中立正面で、眉・視線・目尻・口形・髪の不足動作を整える。その後、各軸の姿勢変形へ展開する。局所動作は後から頭部の姿勢に追従できる階層に置き、正面だけで全表情を完成させようとはしない。

共通原則は [制作Workflow v2.4](../CHARACTER_PRODUCTION_WORKFLOW.md)、実習の根拠は [Lesson 01〜10](../Traning/Cubism_Practical_Production_Lecture.md)。本書はレンの作業順・確認対象を管理する。

## 2. 作業開始前に基準モデルを確定する

- [初期動作の受入記録](model/head_neck_hair/acceptance_20260925.md)を基に、了承済みプレビューと編集用CMO3の対応を確認する。同名の作業版には検査後の未確認差分がある。
- 採用するCMO3を別の作業コピーとして保持し、中立・瞬き・通常会話口・髪を再確認する。元モデルを上書きしたり、静止PSDから既存リグを再生成しない。
- head_angles/single_endpointの輪郭トレース・再メッシュ実験は、自動的に採用しない。
- パラメータ名の存在と、実際に変形が登録され動作することを区別する。今回の棚卸しはREADMEとCDIの確認であり、EditorやRuntimeの再検査ではない。

## 3. 中立正面で整える動き

XYZ=0、髪の物理を一時停止した比較から始める。Deformerを追加するか既存ArtMeshのキーで扱うかは現物の階層を確認して決め、不要な階層は増やさない。

| 対象 | 記録上の実装状況 | 次に整える内容・確認点 |
| --- | --- | --- |
| 瞬き・会話口・顎 | 初回動作は9/25了承済み | 基準として保持。新しい表情と組み合わせた時の線・接続を再確認 |
| 眉 | 動作実装の確認記録なし | 左右の上下・角度・形。まず必要な範囲から作り、髪への潜り方と中立復帰を確認 |
| 虹彩・視線 | EyeBall X/YのIDはあるが動作確認なし | 虹彩・瞳孔・必要なハイライトを一緒に移動。左右上下と斜め、白目内のクリッピング、半閉眼との組合せを確認 |
| 目尻・まぶたの表情 | 瞬き以外の形状動作は確認なし | 笑顔目・細め目など。瞬きの開閉とは役割を分け、目尻だけが裂けたり二重線にならないよう上下まぶた・まつ毛を連動 |
| 口角・口形 | MouthOpenYは実装済み。MouthFormの実動作は未確認 | 口角下げ／基準／上げ。現在の基準の微笑みを保ち、閉口・小開口・中開口・通常最大開口と組み合わせる |
| 中央前髪・左右横髪・後ろ髪 | 揺れとPhysicsは初回実装済み | 既存を点検・調整。根元固定、毛先の可動量、重なり・隙間を確認 |
| 左右前髪 | 頭頂側の静的な土台として保持されている | 必要な毛束だけ揺れを追加。中央前髪との継ぎ目を保つ |
| アホ毛 | 独自Deformerあり、ParamHairFrontを中央前髪と共有 | 独立した揺れが必要なら出力ParameterとPhysicsを分離する。根元の接続を維持 |

標準IDの候補は、眉のParamBrow系、視線のParamEyeBallX/Y、笑顔目のParamEyeLSmile/ParamEyeRSmile、口形のParamMouthForm。目尻の上下・細め目など追加の表現は、既存パラメータで足りるか確認してから独自IDを検討する。虹彩移動と目尻変形を同じ動きとして扱わない。

提案する実装順：基準確認 → 眉 → 視線 → 目尻・まぶた → 口形 → 髪の不足分と独立制御。髪は手動スライダーで形状を成立させた後にPhysicsを点検し、XYZが整った後で各姿勢からの入力に対する揺れを仕上げる。

中立正面段階の区切りは、各動作が単独で成立し、瞬き・開口との主要な組合せで目立つ破綻がなく、基準へ戻ること。極端な表情や大笑いは別工程とする。

## 4. 各軸方向への土台作り：今回の合意

1. **軸と範囲を決める。** X＝左右を向く、Y＝上下を向く、Z＝首を左右に傾ける。パラメータの±30と実際の回転角度は別。左右表記は画面方向とキャラ方向を明記する。
2. **Y単独、次にX単独の中立と両端を作る。** −30／0／＋30を設計上の基本キー候補とし、他軸を0にして顔・耳・髪・顎・首の関係を整える。正面メッシュ構造を維持し、大きな変化はDeformer、局所補正は必要な部位だけに行う。
3. **補間を見て中間キーを加える。** ±10等は固定の必須位置ではなく、不自然になる位置に必要なキーを置く。キーの数より、中立から端点へつながる軌道を優先する。
4. **XY四隅を生成し補正する。** 四隅生成は作成済みの上下左右の形を組み合わせる機能。立体構造や遠近感を自動的に正しく設計してくれるものではない。Z=0で確認し、調整済みキーを再生成で上書きしない。
5. **Zを組み合わせる。** 頭部の親Rotationで傾け、首は襟側の接続を保ちながら追従させる。既存Zの支点・可動量・キーを確認し、重複する回転を加えない。YZ・XZからXYZの代表姿勢へ確認を広げる。
6. **主要なXYZ複合を仕上げる。** 当初の4パターンは代表的な確認姿勢。独立した4種類のリグを最初から作る意味ではない。その他の端点の組合せも破綻確認し、必要な箇所だけ補正する。
7. **表情・髪・Runtimeで確認する。** 単独端点だけでなく、中間・往復動作、瞬き・口形・開口・視線、実Physicsを確認し、Bossの目視判断で土台を採用する。

## 5. 参考原画と再利用の扱い

- 参考原画は各軸と可動範囲を決めてから用意する。XY四隅の原画はまずZ=0を基準とし、傾きを含める場合は明記する。
- 原画はレンらしさ、姿勢の伝わり方、終点の表情の雰囲気を見るために使う。輪郭の完全トレースやピクセル一致を合格条件にしない。
- 眉・まぶた・口が作る感情は表情側で扱い、共通姿勢へ特定の感情を固定しすぎない。どの表情でも出る歪みや隙間は共通土台側で直す。
- 小さい動きと大きい動きは同じXYZパラメータの異なる範囲を使う。Runtime側で振幅・速度・間を制御する。既存の値に対応する形を変更した時は、以前の動作指示も再確認する。
- 再利用資産は編集用CMO3、階層とParameterの役割、調整手順、確認ポーズ、採用範囲をセットにする。別キャラでは支点・変形量・重なりを合わせ直す。moc3は実行用であり編集正本ではない。
