# 朝霧レン：本体制作の実装計画

更新: 2026-09-19。今回行ったのは資料・所在・参照関係の確認と計画作成。以下の実機作業は未着手。

## 目的と完了条件

リサの既存データで再利用できる機能を確認し、レンの白シャツモデルへ展開する。最初の到達点は30〜60秒の実モデル試作。販売完了とは区別し、その後に両アプリの導入・更新・説明を検証する。

AIパートナー連携プログラム、新衣装一式、雨・濡れ、手指追従を最初の試作条件に加えない。

## P0 リサの入力と環境を固定する

1. [共通プリセット](../presets/README.md)と[risa_reference_v1.json](../presets/risa_reference_v1.json)を起点に、入力モデル・テクスチャ・音声・モーションの所在を確認する。
2. 暫定採用済みの[PunctuationPause v1](../../output/live2d/punctuation_pause_v1/test_report.md)を比較基準とする。モデル候補は[同サンプル内のcmo3](../../output/live2d/punctuation_pause_v1/model/Risa_chest_breath.cmo3)、[model3](../../output/live2d/punctuation_pause_v1/model/Risa_speech_breath.model3.json)。元データは保持し、作業コピーを用意する。
3. Cubism、VTS、nizima LIVEの実際のバージョン・FREE/PRO状態・入力音声機器を記録する。未確認のバージョンを推測しない。
4. メッシュ・パラメータ・デフォーマ・テクスチャ等を調べ、FREEで開く→保存→再読込→実行用書出しを試す。開けることと保存可能なことを区別する。

合格条件：比較基準を再生でき、素材参照が解決し、使用するモデルと設定の版が特定できる。FREE制限に当たる場合は、簡略試作で目的を満たすか、PROが必要かを判断する。トライアルは開始すると42日間が進むため、FREE起動と区別する。現行制限は実装時に公式情報も確認する。

## P1 リサのアプリ別動作を作る

リサのプリセットは制作側の記録であり、VTS/nizima LIVEへそのままインポートできる完成設定ではない。既存生成スクリプトによる自動読込も未実装。必要な値を適用する処理と、アプリ側の設定を分けて作る。

| 共通で確認するもの | VTS | nizima LIVE |
| --- | --- | --- |
| 口の開閉・横幅・丸め | 母音入力と既存パラメータの対応・感度・口閉じ | リップシンク方式と対応する口形状・感度 |
| 瞬き・呼吸・首 | 待機モーションとトラッキングの担当を決める | 自動再生・音声トラッキングの担当を決める |
| 基本表情 | 通常／聞き役／微笑みとキー割当 | 同じ意図の表情とキー割当 |
| 髪等の揺れ | モデルの物理設定と強さを確認 | モデルの物理設定と強さを確認 |

同じ音声で発話・無言・発話開始終了を比較する。口は音声、呼吸は専用制御など、各パラメータの主担当と上書き順を記録し、二重駆動を避ける。表情解除で正常な待機へ戻ることを確認する。

固定音声の句読点・音素時刻による演技と、リアルタイム入力の制御は別方式。固定音声の絶対時刻をライブへ流用しない。音声トラッキングだけで発言の意味に合った感情が付くとは扱わない。

合格条件：同じ短い音声について両アプリの録画・設定を残し、口閉じ、無音中の安定、過剰な首・胴体揺れ、表情と口パクの競合を確認できる。リサの未実装機能は追加作業として明示する。

## P2 レンの原画・パーツ設計

1. 参照画像を特定し、顔・髪・肩の印象、白シャツ、袖丈、手姿勢をBossと合わせる。画像の生成・加工条件と採用理由を残す。
2. 顔〜胸肩で必要な可動範囲を決め、全身の描画範囲とは分ける。試作の表示範囲から商品全体の可動仕様を断定しない。
3. 顔、左右の目・眉、口内・唇、前髪・横髪・後ろ髪、首、肩、シャツ胴・襟・袖などを分ける。動かした時に現れる隠れ部分を補完する。
4. レイヤー名、左右、描画順、口内・髪の重なりを確認する。将来の衣装を見据えて襟・袖を分けるが、未採用衣装までは制作しない。

合格条件：中立姿勢でパーツを再合成して原画の印象が保たれ、想定変形で穴が出ない下地がある。AIによる抽出・補完結果は人が確認する。

## P3 基本リグを制作する

順序案：口と目→眉・視線→軽い顔／首の向き→胸肩の呼吸→髪の物理→基本表情と短いモーション。

- メッシュ生成だけで完成とはしない。変形の形、デフォーマ、キー、クリッピング、可動範囲を作る。
- リサから共通化するのはタイミング・設計の考え方。頂点座標、首の倍率、ニットの皺の変形を白シャツに直接複製しない。
- 共通値→人間型初期値→レン固有補正を分ける。`presets/`内のリサ採用値をレン向けに上書きしない。
- 母音の制御方法は既存口形状とFREE制限を見て選ぶ。5母音のために必ず5個のブレンドシェイプが必要だと決めつけない。

合格条件：保存・再読込・書出しができ、斜め顔＋開口、瞬き＋微笑み、呼吸＋髪揺れ等の組合せで目立つ破綻がない。技術検査とBossによる自然さの評価を分けて残す。

## P4 レンで30〜60秒の試作

仮の45秒構成：通常待機10秒→聞き役10秒→短い発話15秒→微笑みから通常へ10秒。秒数は制作時に調整可。

- VTS用設定とnizima LIVE用設定をそれぞれレンに調整。同じ音声・同程度の画面サイズで比較する。
- 録音音声に対する演技指定はモーション／外部の時刻制御で行う。OBSは主に合成・収録を担当する。
- 台詞音声とBGMを分け、音声入力経路と遅延を記録する。無言で口が閉じることを確認する。
- 本体デモは手動の表情切替でもよい。AI会話プログラムを前提にしない。

合格条件：実モデルの30〜60秒録画、入力音声、アプリ設定、編集用モデル、実行用一式、検証記録がそろう。「口・表情・呼吸が自然」「聞き役が魅力的」をBossが評価できる。

## P5 販売用の仕上げ

試作評価後に商品範囲・価格を決める。必要な表情、対応環境、可動範囲、衣装、モデル本体の同梱物を確定する。

- 新規フォルダへの導入、アプリ再起動、キー競合、表情リセット、音声感度の変更例を確認。
- 旧版相当で購入者設定を変更し、更新後に口パク感度・動き倍率・キー・自作表情がどこまで残るか、両アプリで試す。追加設定の反映とバックアップからの復元も確認する。
- 導入手順、推奨設定と調整例、対応表、更新手順、利用条件、問い合わせ時の必要情報を同梱。
- 販売前に販路の現行条件を確認。AI由来の制作工程、実検証済み環境、モデルの制約を正確に表示。

## 保存先と記録

現時点で作るのは本フォルダの文書だけ。成果物が発生した時に `art/`（原画・パーツ）、`model/`（編集用）、`runtime/vts/`・`runtime/nizima/`（個別設定・実行用）、`validation/`（検査・比較）、`delivery/`（配布版）を本フォルダ内へ追加する案。空フォルダを先行作成しない。

各検証では入力・出力の所在とハッシュ、ツールの版、設定、再現手順、技術結果、目視／試聴評価、未確認事項を残す。PSD・テクスチャ・音声は現行Git除外対象があるため、実体の保管・復元先を記録する。Gitコミットだけで素材バックアップが済んだとは扱わない。

工程記録には担当、指定したモデル・推論強度と観測できた実効値、子Agent数、所要時間（測定時のみ）、手戻りを記載する。記録できない値は未取得とする。
